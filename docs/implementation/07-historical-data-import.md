## 2. Hostile-file handling

* The tar is read by a read-only, dependency-free reader (`lib/tar.mjs`): symlinks, hardlinks, devices, absolute/`..`/backslash/Windows-invalid paths are never touched.
* Every member is classified from **content** (magic bytes), not the extension (`lib/classify.mjs`): product folder accepts only `%PDF` and MP3; editor folder accepts PNG/JPEG/GIF/WebP/MP4. Anything else, extension/content mismatches, dotfiles, executable-style extensions, zero-byte files, images < 256 B and videos < 1 KiB are rejected.
* A streaming scanner looks for `<?php`, phar stubs (`__HALT_COMPILER`), ImageMagick MVG, Apache handler directives in the **whole** file; weaker markers (`<?=`, script tags, shell calls) only in files ≤ 64 KiB (an earlier 2 MiB limit produced 6 false positives on large PNGs: the 3-byte `<?=` occurs by chance in compressed data — tuned and documented).
* Result: **90 rejected** — 77 images < 256 B, 12 non-allow-listed content types (text/bin/svg/php/mvg/bmp), 1 `.htaccess`, 1 MP4 < 1 KiB, and 16 files with hostile markers (php-open-tag, phar-stub, mvg, apache-directive, shell-call, script-tag; several overlap with the size/type reasons). The 20,000,001-byte `A…` blob is rejected as text. Rejected members are **never extracted and never uploaded**; they appear in `legacy_media_staging` as `rejected` with the reason and no storage object.
* Accepted files (1,173, 6.96 GB) were extracted only into `D:\mostqel\aawraq-quarantine\user-files\` (outside the project and any web root, new empty directory) and a file whose full-content scan found a marker would be deleted again.
* **Antivirus:** Windows Defender custom scan of the quarantine directory (`scan-quarantine.ps1`): completed in 27 s, 0 detections, 1,173 files present afterwards, real-time protection on, signatures 1.463.155.0 (2026-11-06). The staging script refuses to run without a clean `defender-scan.json`. Note: Defender *did* quarantine a first draft of a unit-test file that embedded literal web-shell strings; the tests now assemble their hostile byte patterns from fragments at run time (the scanner was not bypassed — the source simply no longer contains signatures).

## 5. The MariaDB importer (built; cannot run on real data today)

`scripts/migration/import-legacy.mjs` + `lib/{transform,importer,source,money,sanitize}.mjs`.

* **Refuses to run** without a signature-checked dump path and a restored, read-only, **local** MariaDB (the VPS is never contacted). Running it now prints the exact missing inputs (exit code 2; `migration-output/import-preflight.json`).
* Pure transforms (unit-tested, `tests/unit/migration-*.test.ts`) implement docs/legacy-audit/14 §3: exact-decimal money parsing (Arabic-Indic digits, thousands separators, rejects; raw string always kept in `legacy_cost_raw` / `legacy_raw_amount` / `legacy_raw`), status maps (books 0/1/2, users, withdraw 2/1/0 from the raw tinyint, request-books), `is_free` 0/2 → `preview`, 1 → `after_purchase`, category/tag JSON → link rows (invalid JSON reported, never guessed), page-slug collisions, editor-image rewriting (M5), HTML sanitising, soft deletes → `archived` + `deleted_at`, test-mode orders kept `test`, derived entitlements (live paid orders only unless `--grant-test-entitlements`).
* **Never imported:** `password`, `default_password`, remember/reset tokens (asserted by tests); users are created in Auth **without a password**, `require_password_reset = true`, no invitation e-mail is sent; soft-deleted users get a banned, password-less Auth row (profiles require one). Gateway `response` JSON is stored with card/token/secret keys redacted.
* `site_infos.payment_mode` is reported but not applied (the new system stays in test mode until a gateway is approved). Commission %, freeze days and minimum withdrawal are imported as numbers and remain listed in `pending_owner_confirmation`.
* **Sensitive phases** (users, orders, affiliates, comments, favourites, contact messages, contributor requests, payout methods) are OFF by default; they need `--sensitive --owner-authorised --confirm "<sentence from --help-confirm>"`; users' phone/country/region additionally need `--include-pii`.
* `--dry-run` runs every transform/validation with **no** reads or writes of the target (tested with a database that throws on first use) and prints V1 row-count reconciliation (+ V8 exact order sum). Real runs record `migration_runs`, `migration_rejects`, `legacy_id_map`; a crashed run is marked `FAILED`.
* Catalog phases are integration-tested against the local DB with MOCK fixture rows (legacy ids 900001+, `is_demo = true`, cleaned up; idempotent on re-run). **The customer/financial loaders (users, orders, affiliate ledger…) are only covered by dry-run unit tests** — orders are append-only by design, so they cannot be exercised on the shared dev DB without leaving residue. They must be rehearsed on a disposable local database (`supabase db reset` after the rehearsal) before any real run.
* Reconciliation V2, V3, V5, V6, V7, V9, V10 are listed as `todo` in the report skeleton until a populated target exists (V1 and V8 are implemented; V6 for media is done by `media-inventory.mjs`).
* `mysql2` is **not** a dependency yet (no dump = nothing to read); the reader loads it lazily and says `npm i -D mysql2` when needed.
* Timezone: legacy timestamps are naive; they are read as UTC (Laravel app timezone is unknown — docs/16). Revisit before import.

## 6. Exact steps once the dump arrives

1. Re-run `npm run migrate:availability` (signature check) and keep the dump outside the repo.
2. Restore into a throw-away local MariaDB bound to `127.0.0.1` (`docker run -d -p 127.0.0.1:33306:3306 mariadb:10.6 …`, see `lib/source.mjs`), create a `SELECT`-only user, `npm i -D mysql2`.
3. Profile the dump (counts, value distributions, JSON shapes, orphan rates, charset `utf8mb4`, timezone); fix the open mapping decisions in docs/16.
4. `LEGACY_DB_* … node scripts/migration/import-legacy.mjs --dump <file> --dry-run`; review the report and rejects with the owner.
5. Real catalog run (no `--sensitive`), then `import-legacy` again for `book_media`: staged files link automatically via `legacy_path` (`storage/app/public/` + `book_media.file`); unmatched rows become placeholders listed as `missing_media`.
6. Stage the still-missing files that the mapping actually references (disk permitting), re-run the media phase.
7. With written owner authorisation: rehearse the sensitive phases on a disposable DB, compare V8/V9, then run for real. Send **no** invitation e-mails from the importer.
8. Owner sign-off on the reconciliation report.
